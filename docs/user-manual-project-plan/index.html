User Manual Project Plan

Author: Nathan Hunt Created for the course TWR2004: Producing Technical Projects February 17, 2026

Overview

Project goal

Design and develop a user manual on the topic "Build a custom desktop gaming PC".\ The manual will define all technical terms and explain the basics of computer hardware. It will guide users through the assembly process with step-by-step instructions. The guide will also provide basic troubleshooting of common issues.

Audience assumptions

The primary audience is adults of any gender, age 18 -- 45, with an interest in putting together their own gaming PC. They have no prior knowledge or experience with computer hardware or PC building. The audience can read at an 8th-grade level. They can handle electronic parts and use hand tools with the necessary dexterity. This project plan includes more details about the required tools and user's abilities in the "Assumptions" section. The manual will still be useful to younger or older audiences that do not fit this demographic.

The audience will have only the user manual available to teach them how to build a gaming PC. The introduction can give tips for choosing PC parts but to avoid giving outdated advice, it won't recommend specific models. The user should have all components on-hand when they begin assembling the PC. The user may be nervous handling fragile or expensive PC components. They will need to be guided through the assembly process step-by-step.

User task analysis

  • Prepare the workspace and gather tools.

  • Install motherboard components (CPU, heat sink, RAM).

  • Install case components and prepare case for motherboard installation.

  • Install the motherboard in the case and connect cables.

  • Install the graphics card and connect cables.

  • Power on the PC and test that all components are working.

  • Install an operating system (Windows or Linux).

Recommendations for contextual help

Contextual help for electronic documents:

  • Links to external resources.

  • Multimedia (build guide videos), software downloads, windows installation

  • How to select components. How to pick parts for your budget. Tips and advice.

  • Internal links to related topics or glossary entries.

  • Descriptive hover / alt text for images and links.

Contextual help for printed manual:

  • Assembly flowchart for complex processes.

  • Callouts for specific, important tasks or warnings.

  • Descriptive diagram / figure titles.

  • Index.

Industry style guides

The user manual will follow the Microsoft Writing Style Guide (Microsoft, 2024). It will use Canadian English spelling and grammar, referencing The Canadian Oxford Dictionary (Barber, 2001) and Editing Canadian English 3^rd^ Edition (Virag, 2015).

Production design plan

Production

  • Content drafting, editing, and peer reviews with Microsoft Word.

  • Design and publishing with MadCap Flare to build multiple outputs.

Distribution

Digital PDF available for download.

  • Widely accessible, users can view in a web browser or on a tablet.

Online help site published with templates available in MadCap Flare.

  • Users on smartphones can view an adaptive online manual.

Plans for a physical user manual.

  • PDF design should consider printing limitations.

  • Limit use of full-colour photos for readability and to reduce printing costs.

Print specifications

Spiral bound user manual:

  • Lays flat on the user's workspace and stays open.

  • Opens 360 degrees, taking up less space (Wiley, 2025).

  • Suitable for short page counts and small print runs (Printing Partners, 2025).

Paper size:

  • A smaller page size would take up less of the workspace.

  • Portrait orientation. The manual may be printed on 5.5" x 8.5", or 8.5" x 11" paper.

Translation / localization plan

After the user manual content is complete, the word document can be sent to a translation and localization service. A typical rate for localization is \$0.12 per word (The Word Point, n.d.). The localized manual should have a similar word count to the English manual, so that the layout and page count is consistent.

Technical terms in the user manual should be localized carefully. For example, the term "CPU" can be translated to French as "UC" or "unité central," but "processeur" is the preferred term in Canadian French (Microsoft, 2026). In some cases, localization uses English words or acronyms instead of direct translations.

Navigation/usability plan

The PDF and print versions will have a table of contents, with numbered sections for major assembly stages. The digital version of the manual will use a hyperlinked table of contents and bookmarks for sidebar navigation in a pdf reader. The print manual could use tab dividers to separate sections if the added costs are not too high.

Assumptions, dependencies, risks, constraints

Assumptions

  • The user has the necessary tools and supplies (screwdriver, scissors, cable ties).

  • The user can align and tighten small screws, cut cable-ties, and complete other tasks that require fine motor skills.

  • The user can manipulate hand tools from a physically restrictive position or awkward angle to access internal parts.

  • The user can handle delicate components with care, align pins with sockets, route cables through small gaps, and turn thumb screws.

  • The user has enough workspace to set out and assemble the case and components.

Dependencies

  • Content writing can't begin until SME interview and topic research have started.

  • Content writing can't start until after the outline is completed.

  • Design and layout can't begin in MadCap Flare until the second peer review is done

  • Layout can't be completed until copyediting is done.

  • Index can't be completed until editing and layout are finished.

  • Publishing can't begin until proofreading and all remaining tasks are done.

Risks

  • Reviewers do not provide feedback by due date.\ Mitigation: communicate with reviewers regularly and allow extra time for editing at the end of development stage.

  • Importing or designing content in MadCap Flare is more difficult than expected.\ Mitigation: consider alternatives for PDF/print production (Microsoft Word, Affinity Designer) and web output.

  • Other assignments use up the time allocated for user manual to meet deadlines.\ Mitigation: carefully schedule the project to allow for parallel work on other courses.

Constraints

  • User manual must be around 40 pages.

  • Fixed deadlines for project milestones:

  • Report on SME interview deadline March 9, 2026.

  • First and second draft peer reviews.

  • Final user manual deadline April 13, 2026.

  • Software is limited to free services or programs licensed through Algonquin College.

Test plan

  • Peer feedback on first and second drafts includes feedback on usability.

  • Ask friends and family to review the document at the end of the development phase. Give the test readers a short survey to assess usability and clarity of content.

  • Have the subject matter expert review the user manual content before layout.

  • After design and layout are finalized, ask a test user for another review.

  • Set up a workspace with PC components and ask a test user to build the PC with the user manual.
